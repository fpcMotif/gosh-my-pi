## 2024-07-06 - Promise Coalescing for File I/O Syncs
**Learning:** Concurrent API requests hitting endpoints like `/api/stats` and `/api/sync` can trigger parallel `syncAllSessions` calls. This causes redundant file system parsing and database writes for the same unchanged data. Simple throttling might drop updates that occur during the sync period.
**Action:** Implemented a `currentSyncPromise` / `nextSyncPromise` coalescing pattern for state-syncing operations. The pattern deduplicates requests when a sync is active, and queues exactly one subsequent sync request (`nextSyncPromise`) to capture any updates that happen while the initial sync is processing. Crucially, `.catch(() => {})` is used before the `.then()` block when promoting the next promise to prevent deadlocks from unhandled rejections skipping the state reset logic. In the queued promise's `.then()`, we promote `nextSyncPromise` to `currentSyncPromise` and clear `nextSyncPromise` *before* executing the work to avoid lock-bypassing race conditions.
