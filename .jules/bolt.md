## 2024-05-18 - [Parallelize Config Discovery]
**Learning:** Sequential `for...of await` loops when reading directories or config files can become a bottleneck, especially when loading settings or extensions from multiple levels (e.g., user, project). The codebase frequently utilizes `Promise.all` but there are several spots where config directory loading in capability providers (like `discovery/builtin.ts`) or custom tools loading loops are done sequentially.
**Action:** When performing I/O heavy operations like discovering multiple directories, favor parallelizing them using `Promise.all` instead of standard `for...of await` loops.
## 2024-05-18 - [Parallelize Config Discovery]
**Learning:** Sequential `for...of await` loops when loading dynamic modules like custom extensions and tools can become a bottleneck, especially when scanning multiple user/project configuration directories. Refactoring these loops to map the operations concurrently using `Promise.all` while maintaining correct iterative handling of results (e.g., error reporting and conflict checking) effectively eliminates the bottleneck.
**Action:** When performing sequential I/O or module imports (e.g., `import()` or `readFile`), use `Promise.all` to fetch resources concurrently and then process their resolved states sequentially to maintain intended stateful behaviors like conflict resolution.
