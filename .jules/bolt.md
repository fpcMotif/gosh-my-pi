## 2025-05-24 - [Promise Coalescing for Backend Analytics Sync]
**Learning:** In the stats dashboard, the React frontend issues multiple concurrent requests (`/api/stats`, `/api/stats/recent`, `/api/stats/errors`) on initial load and polling. The backend middleware intercepted all `/api/` requests and unconditionally called `await syncAllSessions()`. This caused a severe N+1 performance bottleneck where concurrent requests would independently trigger heavy file I/O (parsing JSONL files) and database contention (SQLite writes) multiple times simultaneously.
**Action:** Applied promise coalescing (request deduplication) in `syncAllSessions` by caching the active `_syncPromise`. Any concurrent calls now await the exact same promise instance, guaranteeing that the heavy synchronization logic runs exactly once per wave of requests. This pattern should be standard for any heavy, read-heavy, or synchronizing operations hit by concurrent UI components.
