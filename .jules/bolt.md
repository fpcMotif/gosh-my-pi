## 2025-05-30 - [Parallelize Independent Initialization Paths]
**Learning:** In the pi-coding-agent codebase, custom tools and custom commands were being discovered and mapped into paths efficiently, but the actual module loading (`import()`, resolving default exports, validation) inside `loadCustomTools` and `loadCustomCommands` was being done sequentially in a `for...of` loop. Resolving module imports is an I/O-bound operation, and when loading multiple plugins or modules simultaneously across different providers, this sequential iteration represents a performance bottleneck.
**Action:** When initializing plugin systems or mapping multiple I/O promises (like `loadCapability`, `getAllPluginToolPaths`, etc.), always map the loading processes over a `Promise.all` first so that modules are fetched concurrently. To maintain execution order (e.g., for conflict resolution logic with `seenNames`), await the entire `Promise.all` mapping and then iterate synchronously through the array of resolved results.
