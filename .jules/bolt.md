## 2024-06-06 - Parallelized Promise Loading in Extensibility Loaders
**Learning:** In `packages/coding-agent/src/extensibility/` loaders (tools, commands, extensions), using `for...of` loops with `await` for I/O operations (like `loadExtension`, `loadTool`, `loadCommandModule`) creates a performance bottleneck during agent initialization. The correct pattern is to map the paths to an array of Promises (e.g. `const loadPromises = paths.map(async ...)`), execute them concurrently with `Promise.all`, and then iterate over the resolved results sequentially. This is crucial because iterating sequentially over the *results* preserves name conflict detection, array push ordering, and override logic (e.g., later paths overriding earlier ones), while still getting the speed benefit of parallel I/O.
**Action:** When loading multiple independent modules or reading multiple files from a list of paths during initialization, always structure the code to trigger the I/O concurrently using `Promise.all` while preserving sequential order processing in the subsequent results loop to maintain correct logic flow.
