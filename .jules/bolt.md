## 2024-07-03 - Promise Coalescing for File I/O and DB Reads
**Learning:** In the stats dashboard backend, concurrent API requests from the frontend can trigger redundant heavy operations like syncing all session files (`syncAllSessions`) or aggregating dashboard stats (`getDashboardStats`). Because file syncs can take tens of milliseconds and stats aggregation involves complex DB queries, executing them concurrently for every incoming request wastes CPU and I/O.
**Action:** Apply promise coalescing for these operations in `aggregator.ts`. For read-only operations like `getDashboardStats`, cache a single promise and clear it in the `finally` block to deduplicate concurrent requests. For state-syncing operations like `syncAllSessions`, use a chained `currentSyncPromise` and `nextSyncPromise` pattern to ensure that requests arriving *during* an ongoing sync will trigger one additional execution to catch any new state changes, while still coalescing multiple late-arriving requests into that single follow-up sync.
## 2024-07-03 - Promise Coalescing Error Handling
**Learning:** When implementing the chained `currentSyncPromise` and `nextSyncPromise` pattern, unhandled rejections in the `currentSyncPromise` can cause the `.then` block that resets the chain to be skipped. This leads to both promises being permanently stuck in a rejected state, causing a deadlock where all future calls immediately fail.
**Action:** Always append `.catch(() => {})` before the `.then` block in the queued promise chain. This ensures that the queued execution continues and the state variables are properly reset, even if the preceding execution fails.
