## 2024-07-05 - File reading bottleneck with large JSONL appends
**Learning:** When parsing large `.jsonl` session files where we only need to read recently appended data, using `await Bun.file(path).bytes()` followed by `.subarray(start)` is highly inefficient because it loads the entire file into memory on every read. `Bun.file(path).slice(start).bytes()` is orders of magnitude faster. `Bun.file(path).size` must be used to safely compute the start bounds without throwing an error if the file doesn't exist, but a `try/catch` block for `ENOENT` is still required around the actual read operation to avoid Time-Of-Check to Time-Of-Use race conditions.
**Action:** Use the `Bun.file(path).slice(start).bytes()` pattern for incremental file reading in Bun, safely bounded by `.size`, and retaining `ENOENT` checks for the read.
