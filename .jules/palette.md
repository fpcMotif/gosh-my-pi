## 2025-06-25 - Custom Interactive Elements Keyboard Accessibility Pattern
**Learning:** Custom interactive elements like `<tr onClick>` completely break keyboard navigation unless explicitly handled, leaving out screen reader and keyboard-only users. Applying `role="button"` can override native semantics like table structure, creating unintended accessibility issues.
**Action:** When adding interactive behaviors to non-native controls, always implement manual keyboard support by setting `tabIndex={0}`, creating an `onKeyDown` handler (specifically catching "Enter" and " " to call the action, and `e.preventDefault()` on space to stop page scrolling), and explicitly adding `focus-visible` utility classes (e.g. `focus-visible:ring-2 focus-visible:outline-none`) to guarantee distinct visual focus states without relying on default browser styles or misusing aria roles.
